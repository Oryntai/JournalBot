# Спецификация и происхождение реализации

Исходная точка — два предоставленных скриншота SpikeChat. На них заявлены просмотр удалённых и изменённых сообщений, исчезающие медиа и архив чатов. Экран подключения указывает на штатный раздел Telegram «Автоматизация чатов». Функции внутри оригинального бота по этим материалам видны только на уровне описания.

| Наблюдаемая функция | Внешний контракт и реализация |
| --- | --- |
| Подключение через настройки профиля | `business_connection` передаёт состояние подключения и ID его владельца. Приложение сверяет владельца с настройкой экземпляра и начинает запись после `/enable`. |
| Изменённые сообщения | `business_message` и `edited_business_message` дают Bot API-версии сообщения. Журнал связывает их по сочетанию ID подключения, чата и сообщения. |
| Удалённые сообщения | `deleted_business_messages` содержит ID чата и список ID удалённых сообщений. Журнал ищет последнюю записанную версию каждого сообщения. |
| Архив чатов | Приложение ведёт журнал новых сообщений, правок и удалений. Кнопки владельца открывают списки чатов, последнее состояние каждого сообщения, его предыдущие версии и обычные вложения. |
| Исчезающие медиа | Публичный сервер Telegram Bot API отсеивает самоуничтожающиеся сообщения, в том числе в очереди business-событий. Вложения в журнале ограничены обычными медиа из доступных Bot API-событий. |

Код, формат базы, команды и тексты интерфейса написаны с нуля. Источниками были описание на скриншотах и публичная документация Telegram. Для проверки границы по самоуничтожающимся сообщениям использован публичный серверный код Telegram Bot API. Код, трафик, данные и брендовые материалы SpikeChat не использовались. Работу выполнил один автор без формального разделения исследователя и разработчика.

С версии 0.2.0 обновления Bot API обрабатывает aiogram. SQLite и схема шифрования совместимы с v0.1.x. Индекс фильтров добавляется при открытии существующей базы, его значения получаются через HMAC.
