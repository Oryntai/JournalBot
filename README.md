# Telegram Chat Journal

Самостоятельный Telegram-бот для одного владельца. В личном диалоге с ботом можно открыть архив выбранных чатов и посмотреть, каким было сообщение до правки или удаления.

## Запуск

Нужны Node.js 24+ и отдельный бот от [@BotFather](https://t.me/BotFather). В настройках бота включи **Secretary Mode**. Для запуска достаточно встроенных модулей Node.js.

1. В распакованной папке создай локальный файл настроек.

   ```sh
   (umask 077; cp -n .env.example .env)
   ```

2. Впиши токен BotFather в `TELEGRAM_BOT_TOKEN`. Если знаешь свой числовой Telegram ID, впиши его в `TELEGRAM_OWNER_ID`. Для нового бота можно получить ID командой ниже. Отправь одноразовую команду из терминала в личку боту и скопируй показанный ID в `.env`.

   ```sh
   npm run identify
   ```

3. Сгенерируй ключ и впиши результат в `ARCHIVE_KEY_BASE64`.

   ```sh
   node --input-type=module -e "import {randomBytes} from 'node:crypto'; console.log(randomBytes(32).toString('base64'))"
   ```

4. Запусти один экземпляр процесса.

   ```sh
   npm start
   ```

5. В Telegram открой **Настройки → Автоматизация чатов**, добавь своего бота по `@username` и выбери личные чаты для архива. Затем отправь ему в личку `/start` и `/enable`. В выбранном чате отправь, измени и удали тестовое сообщение. Открой `/archive`, затем `/show ID` с номером записи. Для остановки процесса нажми `Ctrl+C`.

Если `/status` показывает, что бот отключён, переподключи его через «Автоматизацию чатов» при запущенном процессе и дождись обновления статуса.

## Команды

| Команда | Действие |
| --- | --- |
| `/status` | Состояние подключения и записи |
| `/enable` | Начать запись новых сообщений |
| `/disable` | Поставить запись на паузу |
| `/chats` | Список чатов с кодами для фильтра |
| `/archive` | Последнее состояние для каждого из десяти недавних сообщений |
| `/archive КОД` | Записи из выбранного чата |
| `/archive all ДО_ID` или `/archive КОД ДО_ID` | Следующая страница архива |
| `/show ID` | Полный текст, вложения и ссылка на предыдущую версию, если она есть |
| `/purge confirm` | Очистить базу и остановить запись |
| `/privacy` | Что сохраняется и как удалить архив |

Бот присылает одно тихое уведомление на пачку правок и удалений. Содержимое можно открыть командами `/archive` и `/show`.

## Какие данные хранит бот

- Бот начинает запись по `/enable` и работает с личными чатами, доступными через «Автоматизацию чатов». Перед подключением сообщи участникам выбранных чатов об архивировании.
- История начинается с полученных ботом сообщений. Telegram передаёт ID при удалении, поэтому запись об удалении появляется, если бот уже получил и сохранил содержимое. При правке он показывает версии, которые получил до и после неё.
- Архив хранит текст, названия чатов и `file_id` обычных фото, видео, голосовых и других поддерживаемых вложений. Сами файлы остаются в Telegram. Восстановление вложения зависит от того, может ли Bot API повторно отправить его по `file_id`.
- Приложение использует Bot API. Одноразовые медиа, секретные чаты и ранее удалённые сообщения находятся за пределами этого интерфейса. Сообщения с признаком защиты и платные вложения пропускаются. Группы и каналы находятся за пределами этого проекта.
- Срок хранения по умолчанию — 7 дней с даты исходного сообщения. `ARCHIVE_RETENTION_DAYS` принимает целое число от 1 до 90. Сокращение срока затрагивает и существующие записи.
- Содержимое архива в `data/archive.sqlite` шифруется AES-256-GCM. Файл базы и `.env` с ключом хранятся отдельно. Храни ключ отдельно от резервных копий SQLite. При его утрате прочитать старую базу будет невозможно. База привязана к ID бота и владельца.
- При отключении автоматизации или замене ID подключения бот очищает архив и выключает запись. `/purge confirm` очищает серверную базу. Уже открытые записи можно удалить из диалога с ботом средствами Telegram.

## Проверка

```sh
npm test
```

Тесты используют синтетические события и имитацию HTTP-ответов Bot API. Для проверки на реальном Telegram нужен бот с токеном и подключением через «Автоматизацию чатов».
